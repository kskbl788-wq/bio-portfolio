## 关于本仓库

这里是我大学第一个学期的**实验与作业作品集**。整整 16 周的实验代码、数据处理脚本、实验记录与报告，都会按周归档在这个仓库里。

我来自生物工程专业，正在学着用编程把生物学问题变成可以计算、可以复现的东西——这也是这个仓库存在的原因：**让每一次实验都可追溯、可复现、可展示**。

## 每周怎么用（三步走）

以第 3 周为例，在项目根目录打开终端，依次执行：

```bash
# 1. 把本周文件放进对应文件夹（文件名随意，放在 labs/week03/ 里即可）

# 2. 看看这次改动了哪些文件
git status

# 3. 提交并推送到 GitHub
git add labs/week03
git commit -m "第3周：完成 XX 实验"
git push
```

## 术语小课堂

刚接触这些词会觉得陌生，用生物实验的场所打个比方就很好懂：

| 术语 | 大白话解释 |
| :-- | :-- |
| **仓库（Repository）** | 就是**一个带自动存档功能的实验记录本**。你放进去的每个文件、每次修改，它都记得清清楚楚，随时能翻到任何一个历史版本。 |
| **提交（Commit）** | **给记录本拍一张快照**。每次 commit 都是一张"照片"，包含当时所有文件的完整状态，外加一句你写的说明。以后想回到某个时间点，找到那张"照片"就行。 |
| **推送（Push）** | **把本地的记录本同步到云端**。照片先存在你自己电脑上（本地仓库），push 之后才会出现在 GitHub 上，别人才能看到。 |
| **`.gitignore`** | **一张"不用管"的清单**。上面列出文件名或规则，Git 看到就自动跳过。比如 `__pycache__/` 这种电脑自动生成的缓存、`*.log` 日志、`.env` 密钥文件——它们要么没用，要么**绝不能公开**。没这张清单，你的仓库会又胖又乱，还可能泄露密码。 |
| **公开仓库（Public）** | **任何人都能查看的仓库**。适合放作品集，老师同学点开链接就能看。对应的是私有仓库（Private），只有你自己和白名单里的协作者能看。 |
| **克隆（Clone）** | **把云端记录本整本复印到另一台电脑**。换电脑时用 `git clone 仓库地址` 就能拿回全部内容。 |
| **分支 main** | **记录本的主线**。GitHub 现在默认用 `main` 作为主分支名，你所有正式内容都放在这条线上。 |
| **README.md** | **记录本的封面页**。GitHub 会自动把它显示在仓库首页，让别人一眼知道这个仓库是干什么的。`.md` 是 Markdown 格式，用简单符号就能排版。 |
| **个人访问令牌 / 凭据管理器** | **推送时的"钥匙"**。GitHub 不接受账号密码推送，第一次 push 时会弹出浏览器让你授权，授权后 Windows 凭据管理器会帮你把钥匙存好，以后不用重复登录。 |
